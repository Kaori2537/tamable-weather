# Weather Forecast Dashboard

リアルタイム天気予報ダッシュボード - Open-Meteo APIを使用したSPA

## 起動手順

1. プロジェクトディレクトリに移動
```bash
cd tamable-weather
```

2. 依存関係のインストール
```bash
npm install
```

3. 開発サーバーの起動
```bash
npm run dev
```

4. ブラウザで http://localhost:3000 にアクセス

## 技術選定理由

### フレームワーク: Next.js 15.5.4
- **理由**: App Routerによる最新のReact開発体験、SSR対応、パフォーマンス最適化、プロダクション向けの機能が豊富
- **使いこなし**: コンポーネントベースの設計、動的インポート、メタデータ管理、ビルド最適化
- **企業採用実績**: Vercel、Netflix、TikTok、Huluなど大手企業が採用
- **開発現場の現実**: 多くの企業が「React + Next.js」を標準スタックとして採用し、React単体で開発することは少なくなっている

### データフェッチ: SWR
- **理由**: 軽量、キャッシュ機能、リアルタイム更新、エラーハンドリング
- **使いこなし**: 自動リフェッチ、楽観的更新、レート制限対応

### チャート: Recharts
- **理由**: React特化、レスポンシブ対応、カスタマイズ性、TypeScript対応
- **使いこなし**: カスタムツールチップ、グラデーション、アニメーション

### 日付処理: date-fns
- **理由**: 軽量、モジュラー設計、Immutable、Tree-shaking対応
- **使いこなし**: タイムゾーン処理、フォーマット、期間計算

## 工夫点

### 1. コンポーネント設計
- **責務分離**: 各コンポーネントが単一の責任を持つ
- **再利用性**: Props型定義による型安全なインターフェース
- **状態管理**: ローカル状態とグローバル状態の適切な分離

### 2. パフォーマンス最適化
- **メモ化**: useMemo, useCallbackによる不要な再計算防止
- **キャッシュ**: SWRによるAPIレスポンスキャッシュ
- **レート制限対応**: 重複リクエスト防止、エラー時のリトライ制限

### 3. UX/UI改善
- **レスポンシブ**: モバイル・タブレット・デスクトップ対応
- **アクセシビリティ**: ARIA属性、キーボードナビゲーション
- **エラーハンドリング**: 適切なエラーメッセージと回復オプション

### 4. データ管理
- **型安全性**: TypeScriptによる実行時エラー防止
- **永続化**: localStorageによるユーザー設定保持
- **位置情報**: 座標から県名の自動判定
  - 現在地から都市を自動追加、LocalStorageで永続化、削除機能付き

## 既知の制約

### API制約
- **Open-Meteoレート制限**: 日10,000、時5,000、分600リクエスト
- **非商用利用**: 商用利用時は有料プランが必要
- **帰属表示**: API提供元のクレジット表示必須

### 技術制約
- **位置情報精度**: ブラウザの位置情報精度に依存
- **座標判定**: 県境付近で誤判定の可能性
- **ブラウザ対応**: 位置情報API非対応ブラウザでの制限

### 機能制約
- **都市数**: デフォルト5都市、位置情報で追加可能
- **期間**: 48時間または7日間のみ
- **指標**: 4つの指標のみ対応（気温、体感温度、降水量、風速）
